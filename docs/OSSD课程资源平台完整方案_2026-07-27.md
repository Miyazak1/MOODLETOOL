- 后台管理员登录。
- 后台用户管理：新增老师、修改密码、启用/停用、分配课程。
- 用户文件持久化：`data/portal-users.json`。
- 密码哈希保存：scrypt。
- 课程状态门禁：`active` / `archived`。
- 后台课程启用/归档状态面板。
- 归档课程会从前台隐藏，直链访问返回 423。
- 课程归档/启用脚本底座：`npm run archive:course`、`npm run activate:course`。
- 后台长任务式课程归档/启用：生成归档包、归档并删除 active、从归档包恢复。
- 生产大文件传输：支持 Node 鉴权后通过 Nginx `X-Accel-Redirect` internal location 传输。
- GitHub-first 代码发布：本地完成修改和验证后先推送 GitHub，服务器通过 `git pull` 更新代码；`npm run package:baota` 只作为应急发布包，不作为主流程。
- 生产环境变量检查：`npm run check:production-env -- --env .env.production`，用于阻止空密钥、默认密码和错误路径上线。
- 生产环境变量生成器：`npm run generate:production-env -- --out .env.production --courses ENG3U,ESLEO --domain your-domain.com`，用于自动生成强随机密钥和首批账号。
- 生产启动入口：`npm run start:production` 会先加载并检查 `.env.production`，通过后再启动网站服务。
- 部署后验收脚本：`npm run smoke:deployed-site -- --base-url https://your-domain --username teacher1 --password ... --course ENG3U`，用于验证线上登录、课程权限、manifest 和文件访问。
- 登录失败限流：教师门户和后台登录都会按 IP、IP+用户名记录失败次数，默认 8 次失败后锁定 15 分钟。
- 指定课程上线 gate：`npm run check:launch-courses -- --courses ENG3U,ESLEO`，用于只检查准备先上线的课程，避免未处理课程的 warnings 淹没发布判断。
- 首批课程数据迁移清单：`npm run prepare:launch-transfer -- --courses ENG3U,ESLEO`，用于生成课程大文件上传到宝塔数据盘的 rclone/rsync 命令和体量报告。
- 首批课程状态初始化：`npm run prepare:launch-status -- --courses ENG3U,ESLEO --out deployment/launch-course-status.json --force`，用于生成服务器 `course-status.json`，只开放首批完成课程，其余课程先归档隐藏。

## 1. 项目定位

本项目是一个私有 OSSD 课程资源平台，服务对象是少数内部教师。它的核心价值不是公开展示课程，而是帮助不熟悉 OSSD 课程体系的教师快速理解课程结构，并按课程、Unit、Lesson 找到备课、授课、布置作业、复习和评估所需资源。

平台最终部署在云服务器上，通过账号登录访问。未经分配课程权限的教师不能看到课程，也不能通过直接文件链接访问课程资料。

当前项目原则：

- 每门课按 Unit 结构组织。
- 每个 Unit 下按 Lesson 结构组织。
- 一次优先完整处理一门课程，再进入下一门。
- 课程内容必须来自 Moodle、真实课程文件或公开真实资源，不能自行生成教学内容。
- iSpring、视频、PDF、HTML、DOCX 等资源需要支持在线查看或播放，并尽可能支持下载。
- 网站后台保留上传、课程管理、用户管理能力，但主要数据整理仍可由 Codex 协助完成。

## 2. 课程结构标准

课程页面必须以教师备课路径为主线，而不是以文件类型为主线。

推荐结构：

```text
Course
  Course Overview
    Course Outline
    Course Introduction
    Course-level Resources
    Textbook / Literature Index

  Unit 1
    Unit Overview
    Unit Plan
    Lessons
      Lesson 1
        Lesson Plan
        Lesson Expectations
        Lesson
          Introduction / Moodle lesson text
          iSpring embedded player
          Lesson files, such as KWL chart
        Hands On
          Moodle page intro
          Quiz / H5P / Video if present
        Consolidation
          Moodle page intro
          Video / H5P / Exit ticket if present
        Homework
          Moodle page intro
          Assignment files
        Other local resources
      Lesson 2
      ...

  Unit 2
  ...
```

需要避免的结构：

```text
Course
  All Outlines
  All Lesson Plans
  All PDFs
  All Videos
  All iSpring
```

原因是教师备课时首先需要理解课程顺序和上下文，而不是先按文件类型搜索。

## 3. 内容来源规则

本项目对课程内容来源有严格限制。

允许来源：

- Moodle 课程页、Book、Assignment、Folder、Resource 中的真实内容。
- Moodle 中引用的 iSpring / H5P / 视频 / 文件。
- 学校已有 course outline、unit plan、lesson plan、teacher notes、worksheets。
- 真实公开资源，例如 Project Gutenberg、Wikisource 等公共领域文本。
- 用户提供的正式课程文件。

不允许：

- 为了补空白而自行编写 lesson 内容。
- 自行生成 quiz、lesson introduction、teacher notes。
- 自行改写 Moodle 原文后冒充原课程内容。
- 在未确认来源的情况下添加教材或文学作品。

如果某课程资料存在缺口，状态应标记为：

- `Plan pending`
- `Lesson plan pending`
- `Needs review`
- `Missing local file`
- `External only`

而不是用生成内容填补。

## 4. iSpring 与视频处理规则

iSpring 是本项目最重要、也最占空间的资源类型。

处理规则：

- Moodle Book 页面中如果有 Hexstruct / iSpring embed，需要镜像为本地 HTML5 package。
- 本地播放入口应指向本项目内的 `presentation.html`。
- iSpring 内部引用的视频、音频、图片、JS、CSS、字体必须完整下载。
- 不能只保存外部 iframe，否则部署后仍依赖第三方播放器。
- 不能只下载外壳而漏掉 `data/video*.mp4`。
- iSpring 下载包可以保留，也可以按需生成。

标准本地结构：

```text
courseware-active/ESLEO/ispring-localized/unit-01/U01L01/
  presentation.html
  data/
    player.js
    slide1.js
    video1.mp4
    img0.jpg
```

只有压缩包时不能在线播放：

```text
courseware-archive/ESLEO.tar.zst
```

必须先解压为 active 状态，才能在线播放。

## 5. 当前已验证课程体量

截至 2026-07-27，本地已重点处理的课程体量如下：

```text
ENG3U 约 9.55GB
ESLEO 约 3.96GB
```

两门平均约：

```text
6.75GB / 门
```

按 30 门课粗略估算：

```text
30 × 6.75GB ≈ 203GB
```

但实际部署不能只按 203GB 购买，因为还需要考虑：

- iSpring 解压包和 iSpring 下载 zip 的重复占用。
- 视频课程会显著大于平均值。
- 上传临时目录、解压临时目录、日志、备份。
- 后续补齐课程资源后的增长。

建议数据盘：

```text
短期上线已完成课程：200GB
30 门课较稳妥：500GB
长期完整资料库：1TB
```

如果采用冷热归档机制，30 门课可以先用 300GB 到 500GB 数据盘，但更推荐 500GB 起步。

## 6. 服务器配置建议

项目访问人数预计少于 5 人，性能压力主要来自视频播放和文件下载，CPU 压力较低。

推荐配置：

```text
云厂商：阿里云 ECS
实例：通用算力型 u1 或同级别实例
CPU：2 核
内存：4GB
系统盘：40GB ESSD Entry / ESSD PL0
数据盘：500GB ESSD Entry 起步
带宽：5Mbps 固定带宽，或按量带宽封顶 5-10Mbps
系统：Ubuntu 22.04 LTS 或 Debian 12
架构：x86_64
```

可省钱配置：

```text
CPU：2 核
内存：2GB
数据盘：200GB - 300GB
带宽：3Mbps
```

但不推荐长期使用 2GB 内存。宝塔、Node、Nginx、文件解压和打包同时存在时，2GB 容易吃紧。

推荐购买：

```text
2 核 4GB + 40GB 系统盘 + 500GB 数据盘 + 5Mbps 带宽
```

## 9. 账号与权限系统

本项目必须上线账号系统，否则课程文件链接泄露后，外部人员也可能访问资源。

```text

课程管理员
老师
只读老师，可选
```

权限说明：

超级管理员：

- 管理所有用户。
- 管理所有课程。
- 上传、删除、启用、归档课程。
- 分配教师课程权限。
- 查看操作日志。

课程管理员：

- 管理被授权课程。
- 上传该课程文件。
- 更新 manifest。
- 查看该课程资源状态。

- 只能查看被分配课程。
- 可以在线播放 iSpring / 视频。
- 可以下载被允许下载的文件。

只读老师：

- 只能查看，不允许下载敏感文件。

- 课程分配。

- 操作日志。

## 10. 文件访问鉴权

不能只靠前端隐藏课程。文件访问必须后端鉴权。

错误做法：

```text
/courseware/ESLEO/ispring-localized/unit-01/U01L01/presentation.html
```

如果这个路径由 Nginx 直接公开，任何拿到链接的人都能访问。

正确做法：

```text
用户请求课程文件
  -> Node 后端检查登录状态
  -> 检查用户是否有该课程权限
  -> 有权限才返回文件
```

大文件和视频推荐使用 Nginx `internal` 或 `X-Accel-Redirect`：

```text
浏览器请求 /files/ESLEO/...
Node 检查权限
Node 返回 X-Accel-Redirect 到 Nginx internal 文件路径
Nginx 负责高效传输视频/PDF/ZIP
```

这样既能鉴权，也不会让 Node 承担所有视频流量。

## 11. 冷热归档机制

为节省数据盘空间，平台需要支持课程冷热状态。

状态：

```text
已启用 active
已归档 archived
正在解压 extracting
正在归档 archiving
异常 error
```

已启用：

- 课程目录已解压。
- 可以在线播放 iSpring。
- 可以查看 PDF/HTML。
- 可以下载文件。

已归档：

- 只保留压缩包。
- 不能在线播放。
- 前台可隐藏，或显示“需管理员启用”。

启用流程：

```text
管理员点击启用课程
  -> 检查 archive 是否存在
  -> 解压到 courseware-active
  -> 校验 manifest 和关键文件
  -> 标记课程 active
  -> 前台可访问
```

当前脚本命令：

```text
npm run activate:course -- --course ESLEO --archive-root /www/wwwroot/ossd-portal/courseware-archive --target-root /www/wwwroot/ossd-portal/courseware-active
```

归档流程：

```text
管理员点击归档课程
  -> 将 courseware-active/COURSE 压缩为 courseware-archive/COURSE.tar.zst
  -> 校验压缩包存在
  -> 校验文件数量
  -> 校验关键文件
  -> 校验通过后删除 active 目录
  -> 标记课程 archived
```

删除 active 目录前必须校验，不能压缩失败后直接删除。

当前脚本命令：

```text
npm run archive:course -- --course ESLEO --source-root /www/wwwroot/ossd-portal/courseware-active --archive-root /www/wwwroot/ossd-portal/courseware-archive
```

确认归档包可读取、包含 `course-manifest.json` 后，如果确实要释放空间，再显式增加：

```text
--delete-active
```

本地/Windows 默认归档为 `.zip`，Linux 默认归档为 `.tar.gz`。后续服务器安装 `zstd` 后，可继续升级为 `.tar.zst`。

推荐压缩格式：

```text
服务器内部归档：tar.zst
兼容 Windows 分发：zip
```

如果只在服务器内部使用，优先 `tar.zst`。

## 12. iSpring ZIP 存储策略

iSpring 会产生重复存储：

```text
解压版 HTML5 package
可下载 ZIP 包
归档课程包
```

长期全部保留会占用大量空间。

推荐策略：

```text
active 状态：保留解压版，用于在线播放
download zip：按需生成或定期清理
archive 状态：只保留课程归档包
```

如果老师很少下载完整 iSpring 包，可以不长期保存每个 lesson 的 iSpring zip，而是在点击下载时临时打包。

## 14. 课程处理流程

每门课处理顺序：

```text
1. 登录 Moodle
2. 抓取 Course 页面结构
3. 抓取 Moodle Book 原始章节
4. 建立 Unit / Lesson 结构
5. 下载 course outline / unit plan / lesson plan
6. 下载 lesson 内 DOCX / PDF / 视频 / H5P
7. 镜像 iSpring
8. 解压 iSpring presInfo 并补齐 video/audio
9. 生成 book_sections 页面
10. 建立教材与文学作品索引
11. 校验 manifest
12. 本地 build
13. 人工抽查关键 lesson
14. 标记课程完成状态
```

处理原则：

- 一门课完成后再处理下一门。
- 不用未完成课程冒充完成课程。
- 不要保留 Moodle 外链作为正式资源入口，除非资源无法本地化且已标记 `External only`。
- 所有页面内容应来自 Moodle 或真实资源。

## 15. 教材与文学作品索引

英语课程需要额外维护教材与文学作品索引。

规则：

- ENG3U 这类课程需要按 Unit 识别文学作品。
- ESLEO 如果课程实际只涉及 Romeo and Juliet、Of Mice and Men，则只记录真实出现的核心作品。
- 不根据旧 lesson plan 或猜测添加未在 Moodle Book 中实际使用的作品。
- 公共领域作品可下载保存。
- 版权状态不明确或非公共领域作品可记录名称，但不强制保存全文。

字段建议：

```text
title
author
unit
lessonIds
role
sourceStatus
materials
notes
```

## 17. 安全配置

必须：

- 全站 HTTPS。
- 密码哈希存储，不能明文。
- Session Cookie 设置 HttpOnly、Secure、SameSite。
- 后台路径必须登录。
- 文件访问必须鉴权。
- 登录失败次数必须限制；默认 `LOGIN_RATE_LIMIT_MAX_FAILURES=8`、`LOGIN_RATE_LIMIT_WINDOW_SECONDS=900`、`LOGIN_RATE_LIMIT_LOCK_SECONDS=900`。
- 宝塔面板端口只允许管理员 IP。
- SSH 端口只允许管理员 IP 或改为密钥登录。
- 定期更新系统和宝塔环境。

建议：

- 操作日志。
- 管理员账号启用强密码。
- 上传文件扩展名白名单。
- 禁止上传可执行脚本。
- 上传文件先进入临时区，再由后台归档入库。

```text
git add .
git commit -m "Prepare OSSD course portal deployment"
git push origin main
```

服务器首次部署主流程：

```bash
cd /www/wwwroot
git clone <your-github-repo-url> ossd-course-portal
cd /www/wwwroot/ossd-course-portal
npm install
npm run build
cp .env.production.example .env.production
npm run check:production-env -- --env .env.production
npm run start:production
```

服务器后续更新主流程：

```bash
cd /www/wwwroot/ossd-course-portal
git pull
npm install
npm run build
npm run check:production-env -- --env .env.production
pm2 reload ossd-course-portal
```

如果使用宝塔 Node 项目管理器，则由宝塔负责启动 `npm run start:production`；如果使用 PM2，则把服务名固定为 `ossd-course-portal`，后续更新时执行 reload。

GitHub 仓库只保存网站代码、脚本、配置模板和小型 metadata；课程大文件、账号数据、生产环境变量和发布 zip 不进入 Git 仓库。课程大文件仍走服务器数据盘：

```text
/www/wwwroot/ossd-portal/courseware-active
/www/wwwroot/ossd-portal/courseware-archive
```

首批只上线完成课程时，还必须生成课程状态文件：

```text
npm run prepare:launch-status -- --courses ENG3U,ESLEO --out deployment/launch-course-status.json --force
```

把生成的课程状态文件放到服务器：

```text
/www/wwwroot/ossd-portal/data/course-status.json
```

这个文件会把 ENG3U、ESLEO 标记为 `active`，把其他 catalog 课程标记为 `archived`。没有这个文件时，未写入状态的课程默认按 active 处理，不适合首批只开放完成课程的部署方式。

## 20. 当前结论

本项目应从“静态课程展示网站”升级为“私有课程资源平台”。

最终形态：

```text
少数教师登录
只看到被分配课程
按 Unit / Lesson 理解课程
在线查看 Moodle Book 内容
在线播放本地 iSpring / 视频 / H5P
下载 DOCX / PDF / ZIP
管理员后台上传和归档
不常用课程压缩保存
需要时解压启用
```

推荐服务器：

```text
阿里云 ECS
2 核 4GB
40GB 系统盘
500GB 数据盘
5Mbps 带宽
Ubuntu 22.04 / Debian 12
宝塔 + Nginx + Node.js 22
SQLite 起步
```

这个配置足够支撑 5 人以内使用，并为 30 门课程的逐步上线留出比较稳妥的空间。

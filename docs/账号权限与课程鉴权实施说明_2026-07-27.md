# 账号权限与课程鉴权实施说明

更新时间：2026-07-27

## 当前已落地能力

本项目已从公开静态课程门户升级为带登录和课程权限控制的私有门户基础版。

当前实现：

- 门户登录页：`/login`
- 登录 API：`/api/portal/login`
- 退出 API：`/api/portal/logout`
- 当前用户 API：`/api/portal/session`
- 课程目录过滤：`/course-catalog.json` 只返回当前用户可访问课程
- 课程路线图过滤：`/course-roadmap.json` 只返回当前用户可访问课程
- 课程 manifest 鉴权：`/courseware/COURSE/course-manifest.json`
- 课程文件鉴权：`/courseware/COURSE/...`
- 顶部显示当前登录用户和退出按钮
- 后台用户管理：`/teacher-admin.html` 登录后可新增老师、修改密码、启用/停用账号、分配课程
- 用户持久化：首次启动会生成 `data/portal-users.json`，后续后台修改直接写入该文件
- 密码存储：后台保存后使用 scrypt 哈希，不再明文保存
- 课程状态门禁：后台可将课程设为 `active` / `archived`；归档课程会从前台隐藏，直链访问返回 423

## 用户配置方式

当前版本以 `data/portal-users.json` 作为运行时用户库。第一次启动时，如果用户库文件不存在，服务器会从环境变量初始化用户；初始化之后，后台页面的“用户与课程权限”会直接更新用户库文件。

示例：

```text
PORTAL_AUTH_ENABLED=1
PORTAL_SESSION_SECRET=replace-with-a-long-random-secret
PORTAL_COOKIE_SECURE=1
PORTAL_USERS_JSON=[{"username":"admin","password":"CHANGE_ME_ADMIN_PASSWORD","role":"admin","courses":["*"]},{"username":"teacher1","password":"CHANGE_ME_TEACHER_PASSWORD","role":"teacher","courses":["ENG3U","ESLEO"]}]
PORTAL_DATA_DIR=/www/wwwroot/ossd-course-portal/data
COURSE_STATUS_FILE=/www/wwwroot/ossd-course-portal/data/course-status.json
COURSE_ACTIVE_ROOT=/www/wwwroot/ossd-portal/courseware-active
COURSE_ARCHIVE_ROOT=/www/wwwroot/ossd-portal/courseware-archive
X_ACCEL_COURSEWARE_PREFIX=/_protected_courseware/
```

字段说明：

```text
username  登录账号
password  初始登录密码；写入用户库后会转为 passwordHash
role      admin / teacher
status    active / disabled
courses   可访问课程列表，["*"] 表示全部课程
```

也可以用 `PORTAL_USERS_FILE` 指定用户库完整路径：

```text
PORTAL_USERS_FILE=/data/ossd-course-portal/portal-users.json
```

课程启用/归档状态默认保存在：

```text
data/course-status.json
```

也可以用 `COURSE_STATUS_FILE` 指定完整路径。

本地默认：

```text
admin / local-admin-password     可访问全部课程
teacher / teacher-password       可访问 ENG3U、ESLEO
```

本地默认账号只用于首次生成用户库。正式服务器必须修改默认密码。

## 权限规则

如果未登录：

- 访问首页会跳转 `/login`
- 访问课程文件会跳转 `/login`

如果已登录但无课程权限：

- 课程不会出现在左侧课程列表
- 直接访问该课程 manifest 返回 403
- 直接访问该课程文件返回 403

如果课程被管理员设为 `archived`：

- 课程不会出现在前台课程列表
- 课程不会出现在前台 roadmap
- 直接访问该课程 manifest 返回 423
- 直接访问该课程文件返回 423
- 管理员需要先在后台把课程设回 `active`

管理员：

- `role=admin` 或 `courses=["*"]` 可访问全部课程
- 可以登录 `/teacher-admin.html` 后维护用户和课程分配

老师：

- 只能访问 `courses` 中列出的课程

## 与后台上传的关系

现有后台上传系统仍使用原来的 admin session：

```text
ADMIN_UPLOADS_ENABLED=1
ADMIN_USERNAME=
ADMIN_PASSWORD=
ADMIN_SESSION_SECRET=
```

门户登录和后台上传登录目前是两套基础机制：

- 门户登录：控制老师能看哪些课程
- 后台登录：控制谁能上传和维护内容

生产环境可以先让同一个管理员账号同时配置到两套环境变量中。后续再统一迁移到 SQLite 用户表。

后台现在已经具备基础用户管理 API：

```text
GET    /api/admin/users
POST   /api/admin/users
DELETE /api/admin/users?username=...
```

这些 API 需要先通过后台管理员登录，不对普通老师开放。

后台也具备第一版课程启用/归档 API：

```text
GET  /api/admin/course-status
POST /api/admin/course-status
```

后台还可以启动真正的课程归档/启用任务：

```text
GET  /api/admin/course-lifecycle-jobs
POST /api/admin/course-lifecycle-jobs
```

这些任务会调用服务器脚本生成归档包或从归档包恢复 active 目录。后台任务是非阻塞的，点击后返回 job id，页面可刷新任务状态。

命令行也可以直接执行：

```text
npm run archive:course -- --course COURSE --source-root /path/to/courseware-active --archive-root /path/to/courseware-archive
npm run activate:course -- --course COURSE --archive-root /path/to/courseware-archive --target-root /path/to/courseware-active
```

只有在确认归档包可读取并包含 `course-manifest.json` 后，才可以给归档命令或后台归档任务启用“删除 active”。

## 上线注意事项

生产环境必须修改：

```text
PORTAL_SESSION_SECRET
ADMIN_SESSION_SECRET
所有默认密码
```

生产环境还建议备份：

```text
data/portal-users.json
data/course-status.json
courseware/
```

如果课程大文件放在独立数据盘，建议将 `PORTAL_DATA_DIR`、`COURSE_STATUS_FILE` 和课程文件目录都放在数据盘，并用宝塔/系统定时任务备份 `data/portal-users.json`、`data/course-status.json`。

## 生产文件传输

生产环境不要用 Nginx 直接 `alias /courseware/`，否则会绕过 Node 的登录和课程权限检查。

推荐模式：

```text
浏览器请求 /courseware/ENG3U/...
Node 检查门户登录、课程权限、课程 active 状态
Node 返回 X-Accel-Redirect: /_protected_courseware/ENG3U/...
Nginx internal location 读取 COURSE_ACTIVE_ROOT 下的真实文件
```

对应环境变量：

```text
X_ACCEL_COURSEWARE_PREFIX=/_protected_courseware/
```

对应 Nginx：

```nginx
location /_protected_courseware/ {
    internal;
    alias /www/wwwroot/ossd-portal/courseware-active/;
}

location /courseware/ {
    proxy_pass http://127.0.0.1:8891;
}
```

生产环境建议开启：

```text
PORTAL_COOKIE_SECURE=1
ADMIN_COOKIE_SECURE=1
```

只有 HTTPS 下 Secure Cookie 才能正常工作。

## 后续升级

下一阶段如果账号数量明显增多，再迁移到 SQLite：

```text
users
  id
  username
  password_hash
  role
  status

course_assignments
  user_id
  course_code

audit_logs
  actor
  action
  target
  created_at
```

目前后台页面已经可以新增老师、修改密码、勾选课程；SQLite 主要用于更复杂的审计、搜索、批量导入和更稳的并发写入。

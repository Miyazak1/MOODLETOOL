# 前台 Banner 与后台管理员面板前端优化方案

日期：2026-08-26

适用项目：OSSD Course Portal

## 1. 背景

本次优化不是局部样式修补，而是一次面向课程资源门户和管理员工作台的中型前端体验升级。

当前项目有两个主要前端面：

- 前台课程门户：React 单页应用，入口为 `src/main.tsx`，样式集中在 `src/styles.css`。
- 后台管理员面板：静态页面 `public/teacher-admin.html`，配合 `public/admin-*.js` 模块渲染各管理面板。

已通过登录后的内置浏览器实际查看前台与后台页面，覆盖窄屏约 505px 宽度与桌面宽度约 1440px。浏览器控制台未发现明显前端错误，但信息架构、首屏组织、默认态反馈和高风险操作分级仍有较大优化空间。

## 2. 当前观察

### 2.1 前台课程门户

当前首屏由顶部条、语言/账号/后台入口、课程下拉、当前课程卡、搜索框、Unit 导航组成。

在窄屏下，真正的课程 overview 区块被推到约 1200px 以下，首屏几乎只显示导航和选择控件。用户进入页面后很难第一眼获得：

- 当前课程的完整名称、状态和定位。
- 课程完整度、资源覆盖、可用入口。
- 继续备课或查看资料的主操作。

桌面端虽然信息更充足，但课程概览、统计、资源入口与 Unit 导航仍分散在不同块里，不够像一个清晰的课程工作台入口。

### 2.2 后台管理员面板

后台登录后功能完整，左侧导航分组、当前课程上下文、dashboard、媒体发布、课包导入、生命周期、存储和用户管理均已具备。

桌面端结构可用：左侧导航 + 右侧工作区成立。主要问题是：

- 顶部 banner 和当前课程上下文区纵向占用偏大。
- Dashboard 加载过程中多个卡片显示“读取中”，缺少更自然的 skeleton 或分区加载状态。
- 媒体发布和全课程概览默认态大片空白，像未加载完成，而不是可操作工作台。
- 课程压缩包、归档并删除 active、应用首批上线状态等高风险操作视觉分级不足。
- 移动端会先显示完整后台侧栏，核心 dashboard 被推到很下面。
- 后台 CSS 内嵌在 `teacher-admin.html`，体积大，维护和后续迭代成本高。

### 2.3 已发现的具体样式债

后台样式引用了未定义的 CSS 变量：

- `var(--blue)`
- `var(--green)`

这些变量用于媒体结果链接、OSS 进度条和上传队列进度条等位置，应在改版第一阶段统一修复。

## 3. 优化目标

### 3.1 前台目标

将前台从“课程资料列表页面”升级为“课程工作台入口”。

目标效果：

- 首屏明确显示课程身份、状态、完整度和主要动作。
- 课程切换、搜索、Unit 导航不再压过课程 banner。
- 老师能快速进入课程资源、Unit、文本、教师备课内容。
- 管理员入口保留，但不抢占老师主流程。
- 窄屏优先优化，桌面端同步增强信息密度。

### 3.2 后台目标

将后台从“表单集合”升级为“运营控制台”。

目标效果：

- 登录后第一屏优先呈现关键状态、风险和下一步操作。
- 当前课程上下文常驻但更紧凑。
- 高风险操作有明确分区、文案和视觉警示。
- 媒体发布、课包导入、生命周期面板具有清晰默认态和任务态。
- 移动端不再先被侧栏占满。
- CSS 可维护性提升，为后续迭代留出结构。

## 4. 设计原则

### 4.1 操作优先级清晰

每个页面和面板最多突出一个主操作，其他操作按次级、辅助、危险分级。

建议按钮分级：

- Primary：当前推荐操作，如“发布当前课程”“上传并导入”。
- Secondary：查看、刷新、跳转类操作。
- Subtle：辅助入口，如“前台查看”。
- Danger：删除、归档并删除、替换课程内容等不可轻易撤销操作。

### 4.2 控制台风格，而非营销页面

项目是课程资源与运维后台，不适合大面积装饰性 hero 或过重视觉特效。应采用安静、密集、清晰、可扫读的工作台风格。

### 4.3 状态先于说明

后台用户首先需要知道：

- 当前课程是谁。
- 是否有风险。
- 是否有任务在运行。
- 下一步可做什么。

说明文字要保留，但不应占据核心位置。

### 4.4 移动端不是缩小版桌面

窄屏下应优先显示当前课程、主操作和关键状态。侧栏导航应改为折叠、分组横向入口或紧凑导航，而不是完整堆在首屏。

### 4.5 保持业务逻辑稳定

本次优化优先调整 DOM 结构、CSS、交互反馈与展示状态，不改变课程导入、媒体发布、生命周期、权限等后端业务接口。

## 5. 推荐实施范围

### 5.1 阶段一：前端基础整理

目标：先让样式系统稳定，降低后续大改风险。

建议修改：

- 新增后台样式文件 `public/admin.css`。
- 从 `public/teacher-admin.html` 中逐步拆出 CSS。
- 统一前后台基础 token：
  - 文本色
  - 边框色
  - 页面背景
  - 主色
  - 成功色
  - 警告色
  - 危险色
  - 信息蓝
- 修复未定义的 `--blue`、`--green`。
- 统一按钮、badge、notice、progress、table、panel 的基础样式。
- 为按钮和导航补充稳定的 focus-visible 样式。

建议产出：

- `public/admin.css`
- 精简后的 `public/teacher-admin.html`
- 更新后的 `src/styles.css`

验收标准：

- `npm run build` 通过。
- `npm run smoke:admin-shell-panel` 通过；`npm run smoke:admin` 优先执行，若本地未配置 OSS 环境则记录集成项失败原因。
- 前后台无 console error。
- 后台按钮、进度条和状态色不再引用未定义变量。

### 5.2 阶段二：前台 Banner 重构

目标：重建前台首屏信息架构。

建议修改：

- 将顶部条和 course overview 重新组织为课程 banner。
- banner 中包含：
  - SunnyBrook OSSD 品牌标识。
  - 当前课程代码和课程标题。
  - Ready / Planning 等课程状态。
  - Units、Lessons、iSpring、Resources、Validation 核心统计。
  - 主要入口：课程资源、Unit Roadmap、Teacher Prep、Admin。
- 课程下拉和搜索在桌面端可放入左侧或 banner 下方工具条；窄屏下应折叠为紧凑控件。
- Unit 导航在窄屏下不要占满首屏，可采用横向滚动 chip、折叠列表或“当前 Unit + 展开全部”模式。
- 当前课程卡可并入 banner，避免重复展示。

建议涉及位置：

- `src/main.tsx`
- `src/styles.css`

验收标准：

- 505px 宽度首屏能看到当前课程标题、关键统计和至少一个主操作。
- 1440px 宽度首屏能同时看到课程 banner、核心统计、课程入口和部分后续内容。
- 课程切换、搜索、Unit 切换、管理员入口仍可用。

### 5.3 阶段三：后台 Shell 和 Dashboard 优化

目标：让后台登录后第一屏像真正的管理控制台。

建议修改：

- 顶部 banner 降低高度，保留品牌、页面标题、登录状态、前台入口。
- 当前课程上下文条改为紧凑 sticky context bar。
- 左侧导航增强：
  - 保留现有分组。
  - active 状态更明确。
  - 桌面端保持侧栏。
  - 窄屏改为折叠导航或顶部 segmented navigation。
- Dashboard 增强：
  - 顶部放 4 个核心 KPI。
  - 风险区优先显示缺口。
  - 存储空间使用率超过 85% 时视觉提醒。
  - 加载态使用 skeleton 或分区“正在读取”，避免整页像空白。
  - 给“今天建议处理”的下一步入口。

建议涉及位置：

- `public/teacher-admin.html`
- `public/admin-shell-panel.js`
- `public/admin-dashboard-panel.js`
- `public/admin.css`

验收标准：

- 登录后桌面首屏可看见 dashboard KPI、风险摘要和主要操作。
- 窄屏首屏不再被完整侧栏占满。
- Dashboard 数据读取中、成功、失败三种状态都清楚。

### 5.4 阶段四：后台核心面板重排

目标：优化高频、高风险管理流程。

#### 媒体发布面板

当前默认态主要是按钮和筛选器，列表为空时空白感明显。

建议：

- 增加媒体状态摘要卡：
  - 当前课程媒体状态。
  - 活跃任务数。
  - 失败/警告任务数。
  - OSS 发布状态。
- 默认无任务时显示明确 empty state：
  - 没有运行任务。
  - 可发布当前课程或刷新媒体状态。
- 自动刷新状态放在面板右上角或状态条中。
- 发布全部资源属于高影响操作，应比“发布当前课程”更弱或需要更明确说明。

#### 课程压缩包面板

当前表单清晰，但“替换课程内容”的风险表达不足。

建议：

- 按步骤展示：
  - 选择导入路径
  - 选择 ZIP
  - 上传/扫描
  - 预览确认
  - 替换课程
- 多文件自动导入勾选项突出风险。
- `确认替换课程内容` 使用危险确认样式。
- 上传状态条固定在表单下方，避免长任务时用户不知道是否在进行。

#### 启用 / 归档面板

当前高风险按钮与普通按钮混排。

建议：

- 分为三个区域：
  - 可见性状态：启用当前课程、归档当前课程。
  - 归档任务：生成归档包、从归档包解压启用。
  - 危险区：归档并删除 active。
- 危险区单独边框和文案说明。
- 原生 confirm 后续可替换为自定义确认面板，但第一轮可以先做视觉隔离。

#### 全课程概览面板

当前默认态只有三个按钮。

建议：

- 默认展示说明卡和三个入口卡：
  - 全课程缺口
  - 上传清单
  - 内容工作台
- 每个入口说明适用场景和会读取的数据。
- 读取后展示摘要，再展示表格。

建议涉及位置：

- `public/admin-media-panel.js`
- `public/admin-course-package-panel.js`
- `public/admin-course-lifecycle-panel.js`
- `public/admin-readiness-panel.js`
- `public/admin-upload-gap-panel.js`
- `public/admin-content-workbench-panel.js`
- `public/admin.css`

验收标准：

- 每个面板默认态都有信息，不出现大片空白。
- 高风险操作视觉上与普通操作分离。
- 操作进行中有稳定反馈。
- 表格在窄屏下可横向滚动且不会破坏页面宽度。

## 6. 不建议本轮做的事

以下内容不建议放入本轮优化，以免扩大风险：

- 重写后台为 React/Vue 应用。
- 改动服务器接口。
- 改动课程 manifest 数据结构。
- 调整课程导入、媒体发布、OSS 上传、归档脚本的业务逻辑。
- 引入大型 UI 组件库。
- 使用重装饰、大图 hero、动效背景等营销页风格。

## 7. 风险控制

当前仓库存在大量已修改或未跟踪的部署与数据产物。执行时应严格控制改动范围。

### 7.1 前台课程展示保护边界

已与前台课程展示修复任务 `codex://threads/01a02319-bd0a-7e80-81f7-3ed04a3dc986` 同步。该任务近期修复了 BBI2O/MHF4U standalone 页面壳、Teacher Prep、同 path 附件合并和 Files 页内展示漏检等问题。

后续 Banner 和后台优化必须视为 app chrome 层改动，不得改变课程内容渲染链路。

必须保护的前台组件和函数：

- `ResourceActions`
- `ISpringActions`
- `CourseMoodleSections`
- `LessonRow`
- `UnitMoodleResources`
- `TeacherPrepPanel`
- `TeacherPrepResources`
- `MoodleEmbedButton`
- `buildCourseMoodleSectionGroups`
- `originalMoodleSectionGroups`
- `moodleEmbedForResource`
- `localOpenProps`
- `hasWebPreview`
- `hasMoodleActivityPage`

必须保护的样式选择器：

- `.moodle-*`
- `.unit-moodle-*`
- `.teacher-prep-*`
- `.lesson-*`
- `.lesson-flow-*`
- `.resource-card*`
- `.resource-actions`
- `.button-link.ispring`
- `.course-quick-nav*`
- `courseware/*/_assets/course-page-shell.css`

禁止使用未限定范围的全局 CSS 改动，例如直接改：

- `main`
- `section`
- `article`
- `h1`
- `button`
- `a`
- `iframe`
- `video`
- `.card`

可优先改动的范围：

- `.topbar`
- `.topbar-actions`
- `.shell`
- `.sidebar`
- 新增 scoped Banner 类，例如 `.portal-banner-*`
- 后台管理员面板独有 class

硬约束：

**Banner/admin 优化不得改变课程 manifest 映射、资源卡片动作、页内嵌入资源、standalone shell、Teacher Prep 渲染逻辑；所有视觉改动必须 scope 到 app chrome 或后台独有 class。**

建议只触碰：

- `src/main.tsx`
- `src/styles.css`
- `public/teacher-admin.html`
- `public/admin.css`
- 必要的 `public/admin-*.js`
- 必要的 smoke test 脚本

避免触碰：

- `deployment/`
- `courseware/`
- `courseware-archive/`
- 课程资源 JSON、预览产物、媒体报告等生成文件

## 9. 分阶段交付建议

### 里程碑 A：设计基础与样式债清理

范围：

- 后台 CSS 拆分。
- token 统一。
- 按钮、表格、状态、进度条基础样式统一。
- 修复未定义 CSS 变量。

建议作为单独提交，便于回滚。

### 里程碑 B：前台 Banner 首屏重构

范围：

- 新课程 banner。
- 课程选择和搜索位置调整。

建议优先完成，因为前台是老师使用频率最高的入口。

### 里程碑 C：后台 Shell 与 Dashboard

范围：

- 顶栏压缩。
- 当前课程上下文条重排。
- 侧栏/窄屏导航优化。
- Dashboard KPI、风险摘要、加载态优化。

### 里程碑 D：后台核心面板交互优化

范围：

- 媒体发布面板默认态和任务态。
- 课程压缩包步骤化。
- 生命周期危险区。
- 全课程概览入口卡。

## 10. 最终验收标准

本轮优化完成后，应满足：

- 前台窄屏首屏能看到课程身份、状态、关键统计和主入口。
- 前台桌面首屏具备清晰课程工作台感觉。
- 后台桌面首屏能直接判断课程状态、完整性风险和存储风险。
- 后台窄屏不再被完整侧栏阻塞主要内容。
- 高风险操作有明确视觉隔离。
- 默认空白态减少，用户知道下一步要做什么。
- 构建和后台 smoke test 通过。
- 不改动课程数据和部署产物。

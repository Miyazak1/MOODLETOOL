# 宝塔 PM2 生产运行说明

本文用于把 OSSD Course Portal 从手动 `node server.mjs` 启动，升级为 PM2 守护进程运行。

## 目标

- 服务器重启后自动恢复网站服务。
- Node 进程异常退出后自动重启。
- 日志固定写入项目目录，便于排查上传、解压、导入失败。
- 仍然保留 `.env.production` 作为唯一生产环境变量来源。

## 一次性安装

在宝塔终端执行：

```bash
npm install -g pm2
pm2 -v
```

确认项目目录：

```bash
cd /www/wwwroot/ossd-course-portal
mkdir -p logs data
npm install
npm run build
```

## 首次启动

```bash
cd /www/wwwroot/ossd-course-portal
npm run pm2:start
pm2 status ossd-course-portal
```

如果状态是 `online`，说明 Node 服务已经由 PM2 接管。

## 设置开机自启

```bash
pm2 save
pm2 startup systemd -u root --hp /root
```

第二条命令会输出一条很长的 `sudo env PATH=... pm2 startup ...` 命令。复制它并执行一次，然后再次执行：

```bash
pm2 save
```

## 日常更新部署

以后从 GitHub 更新项目，用这组命令：

```bash
cd /www/wwwroot/ossd-course-portal
git pull
npm install
npm run build
npm run pm2:restart
pm2 status ossd-course-portal
```

不再使用：

```bash
node server.mjs --root dist --port 8891
```

## 日志位置

PM2 日志：

```bash
/www/wwwroot/ossd-course-portal/logs/pm2-out.log
/www/wwwroot/ossd-course-portal/logs/pm2-error.log
```

查看实时日志：

```bash
npm run pm2:logs
```

查看最近 200 行：

```bash
pm2 logs ossd-course-portal --lines 200
```

上传和导入历史仍在课程目录内：

```bash
/www/wwwroot/ossd-course-portal/courseware-active/<COURSE>/_admin_uploads/upload-history.jsonl
```

如果课程目录配置在数据盘，以上路径以 `.env.production` 的 `COURSE_ACTIVE_ROOT` 为准。

## 常用维护命令

```bash
pm2 status
pm2 restart ossd-course-portal --update-env
pm2 stop ossd-course-portal
pm2 delete ossd-course-portal
pm2 monit
```

检查 PM2 当前启动参数：

```bash
pm2 describe ossd-course-portal
```

## 注意事项

- `ecosystem.config.cjs` 通过 `scripts/start-production.mjs` 启动服务。
- `start-production.mjs` 会读取 `.env.production`。
- PM2 配置里使用了 `--skip-check`，避免没有 HTTPS/域名时启动被生产检查阻断；正式上线 HTTPS 后仍建议手动执行：

```bash
npm run check:production-env -- --env .env.production
```

- 宝塔 Nginx 仍负责 80/443 入口和反向代理到 `127.0.0.1:8891`。
- 如果网站无法访问，先看：

```bash
pm2 status ossd-course-portal
pm2 logs ossd-course-portal --lines 200
curl -I http://127.0.0.1:8891/
```

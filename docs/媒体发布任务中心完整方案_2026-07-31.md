# MoodleTool 媒体发布任务中心完整方案

日期：2026-07-31

## 目标

把现在已经跑通的命令行流程：

```text
视频审计 -> 自动压缩 -> 上传 OSS -> 生成 asset-registry -> CDN 访问 -> 播放验证
```

做成 MoodleTool 管理后台里的完整任务中心。管理员后续上传、导入、更新课程后，不再需要进入宝塔终端手动跑命令，而是在后台直接发起、查看、重试和审计媒体发布任务。

现有课程迁移仍先按命令行跑完，确保当前 4 门课先正确迁入 OSS/CDN。任务中心开发完成后，后续几十门课和新增课程走后台。

## 一句话方案

新增“媒体发布中心”后台模块，后端使用持久化任务队列调度现有 media delivery pipeline，前端提供全量/单课发布、视频审计、压缩、OSS 同步、CDN 预热、状态日志、失败重试和资源覆盖率视图。

## 不重新造轮子

已经存在并应复用的能力：

- `npm run audit:videos`：视频码率审计。
- `npm run optimize:videos`：压缩超标视频。
- `npm run sync:oss`：同步课程资源到 OSS 并生成 `asset-registry.json`。
- `npm run export:cdn-preheat`：导出 CDN 预热 URL。
- `npm run check:media-delivery`：检查 OSS/CDN/ffmpeg/registry 配置。
- `npm run pipeline:media-delivery`：串联以上步骤。
- `COURSEWARE_ASSET_MODE=hybrid`：已上传资源走 CDN，未上传资源回退本地。
- `scripts/lib/course-operation-locks.mjs`：课程级操作锁。

任务中心要做的是把这些脚本变成后台可控任务，而不是重写压缩和上传逻辑。

## 功能范围

### 1. 媒体发布仪表盘

后台新增导航：

```text
媒体发布
```

页面展示：

- 当前媒体配置是否可用：OSS bucket、CDN base URL、asset mode、ffmpeg、ffprobe、ossutil。
- 已发布资源数量。
- 本地课程资源总量。
- OSS/CDN registry 覆盖率。
- 待压缩视频数量。
- 近期任务状态。
- 当前是否有任务运行。
- 最近一次全量检查时间。

### 2. 课程级资源状态

每门课展示：

- 课程代码。
- 本地文件数量。
- 本地资源大小。
- 视频数量。
- 高码率视频数量。
- 已上传 OSS 数量。
- 已走 CDN 数量。
- 未发布资源数量。
- 最近发布任务状态。
- 最近错误。

操作按钮：

- 审计
- 压缩
- 上传 OSS/CDN
- 完整发布
- 重跑完整发布
- 查看日志

### 3. 全量任务

支持全量：

- 全量审计
- 全量压缩
- 全量上传 OSS/CDN
- 全量完整发布
- 全量 readiness 检查

默认不并行执行全量发布。全量发布涉及 `asset-registry.json`，必须串行。

### 4. 任务类型

任务类型统一建模：

```text
audit-videos
optimize-videos
sync-oss
export-cdn-preheat
check-readiness
publish-course
publish-all
```

其中：

- `publish-course` = 审计指定课程 -> 压缩候选视频 -> 上传 OSS -> 导出预热 -> readiness 检查。
- `publish-all` = 全量审计 -> 压缩候选视频 -> 全量上传 OSS -> 导出预热 -> readiness 检查。

### 5. 任务状态

状态机：

```text
queued -> running -> succeeded
queued -> running -> warning
queued -> running -> failed
queued -> cancelled
running -> cancelling -> cancelled
running -> interrupted
```

说明：

- `succeeded`：所有步骤成功，无 warning。
- `warning`：脚本退出成功，但 readiness 或审计存在非阻断 warning。
- `failed`：脚本失败或存在 blocker。
- `interrupted`：服务重启、进程丢失、服务器异常导致任务未正常结束。
- `cancelled`：管理员手动取消。

### 6. 任务日志

每个任务要有独立日志文件：

```text
data/media-jobs/{jobId}/job.json
data/media-jobs/{jobId}/stdout.log
data/media-jobs/{jobId}/stderr.log
data/media-jobs/{jobId}/report.json
```

后台日志支持：

- 实时刷新最近 N 行。
- 展开完整日志。
- 下载日志。
- 显示最终 report。
- 显示执行命令，但隐藏敏感环境变量。

### 7. 失败重试

任务失败后支持：

- 原参数重试。
- 只重试失败阶段。
- 改为 dry-run 重试。
- 单课重试。

默认重试规则：

- 如果是 `sync-oss` 失败，重试时重新扫描本地并跳过已存在/已登记资源。
- 如果是 `optimize-videos` 失败，不覆盖原备份，继续使用已有备份目录或新建备份目录。
- 如果是 `asset-registry.json` 写入失败，必须保留旧 registry，并显示 blocker。

### 8. 取消任务

支持取消 running 任务：

- 后端记录 `cancelling`。
- 向子进程发送终止信号。
- 如果子进程退出，状态设为 `cancelled`。
- 如果服务重启后无法追踪子进程，状态设为 `interrupted`。

注意：OSS 已上传的对象不自动删除。取消只停止后续步骤，不回滚 OSS。

### 9. 上传/导入后自动触发

课程上传或导入成功后可以自动创建媒体任务。

触发点：

- 单文件上传成功后：可选择只审计或发布该课程。
- 课程包 commit 成功后：自动创建 `publish-course`。
- 课程激活/恢复成功后：可选择创建 `publish-course`。

自动触发默认可配置：

```env
MEDIA_JOBS_AUTO_PUBLISH_AFTER_UPLOAD=0
MEDIA_JOBS_AUTO_PUBLISH_AFTER_PACKAGE=1
MEDIA_JOBS_AUTO_PUBLISH_AFTER_ACTIVATE=0
```

建议默认只对“课程包上传完成”自动发布，单文件上传先保守地只提示管理员手动发布。



### 原子写入

所有任务状态文件必须用临时文件原子替换：

```text
job.json.tmp -> rename -> job.json
index.json.tmp -> rename -> index.json
asset-registry.json.tmp -> rename -> asset-registry.json
```

不能直接覆盖写入 JSON，防止服务中断时写出半个文件。

### 锁策略

使用两层锁：

1. 全局媒体发布锁：

```text
data/media-jobs/locks/media-publish.lock
```

用于保护：

- OSS 上传。
- `asset-registry.json` 写入。
- CDN 预热列表生成。

2. 课程锁：

```text
data/media-jobs/locks/course-ENG3U.lock
```

用于保护：

- 同一门课不能同时压缩、上传、归档、恢复。
- 上传/导入流程不能和发布流程同时改同一个课程目录。

规则：

- 全量发布拿全局锁。
- 单课发布拿全局锁 + 课程锁。
- 只审计可以不拿全局锁，但要拿课程读锁或运行前快照。
- 压缩必须拿课程锁。

### 调度器

在 `server.mjs` 中新增内置任务调度器：

```text
mediaJobQueue
mediaJobs
mediaJobWorkers
```

推荐第一版并发：

```env
MEDIA_JOBS_MAX_CONCURRENCY=1
```

原因：

- 现在 OSS 上传和 registry 写入是核心风险。
- 当前需求不是追求后台并行上传，而是稳定地把课程发布出去。
- 等任务中心稳定后，可把纯审计任务放宽到 2-3 并发。

### 子进程执行

后端通过 `spawn(process.execPath, args)` 调用现有脚本。

完整发布命令对应：

```bash
node scripts/run-media-delivery-pipeline.mjs \
  --course ENG3U \
  --courseware-root /www/wwwroot/ossd-portal/courseware-active \
  --apply-optimize \
  --apply-oss \
  --bucket oss://moodletool \
  --cdn-base-url https://cdn.moodletool.work/courseware-active \
  --asset-mode hybrid \
  --ffmpeg /usr/bin/ffmpeg \
  --ffprobe /usr/bin/ffprobe \
  --ossutil ossutil
```

全量发布命令对应：

```bash
node scripts/run-media-delivery-pipeline.mjs \
  --all \
  --courseware-root /www/wwwroot/ossd-portal/courseware-active \
  --apply-optimize \
  --apply-oss \
  --bucket oss://moodletool \
  --cdn-base-url https://cdn.moodletool.work/courseware-active \
  --asset-mode hybrid \
  --ffmpeg /usr/bin/ffmpeg \
  --ffprobe /usr/bin/ffprobe \
  --ossutil ossutil
```

后台应根据任务类型生成参数，不允许前端传任意 shell 字符串。

### 服务重启恢复

服务启动时扫描 `data/media-jobs/index.json`：

- `queued`：继续排队。
- `running`：检查 `pid` 是否存在。
- `pid` 不存在：标记为 `interrupted`。
- `pid` 存在但不是本服务子进程：只读展示，不接管；完成状态需要人工重新检查。

建议第一版服务重启后不接管老进程，只标记“需要人工确认”，避免误杀仍在上传的 nohup 任务。

- 不自动立即发布。

```text
文件已上传。建议运行该课程媒体发布任务，将资源同步到 OSS/CDN。
```

```text

```

### 课程包上传

课程包 commit 成功后：

- 根据配置决定是否自动创建 `publish-course`。
- 默认建议开启。

```env
MEDIA_JOBS_AUTO_PUBLISH_AFTER_PACKAGE=1
```

### 归档/恢复

恢复 active 课程后：

- 不立即自动上传。
- 页面提示管理员检查后发布。

归档课程后：

- 不自动删除 OSS 对象。
- 先保留 CDN/OSS 资源，避免误删导致历史 iframe 访问失败。
- 后续可以增加“归档课程 OSS 清理任务”，但不放在第一版任务中心。

## 安全设计

- 只允许已登录管理员访问媒体任务 API。
- 前端不能传任意 shell 命令。
- 所有 course 参数必须 `safeSegment` + uppercase。
- 任务命令由后端白名单生成。
- 日志中不输出 AccessKey、Secret、Token。
- OSS 继续保持私有 Bucket，通过 CDN 私有 Bucket 回源读取。
- 不在后台提供“公开 Bucket”按钮。

## 并发和一致性

必须防止：

- 两个全量上传同时跑。
- 单课上传和全量上传同时跑。
- 单课压缩和课程包上传同时改目录。
- 上传一半时 registry 被另一个任务覆盖。
- 服务重启后 running 状态永久卡住。

处理方式：

- 媒体发布写操作默认全局串行。
- 任务状态持久化。
- 使用课程锁和全局锁。
- `asset-registry.json` 只允许一个任务写。
- registry 使用原子替换。
- 启动时修复 orphan running job。

## 任务执行摘要解析

现有 pipeline 会输出 JSON summary。任务中心应解析：

- `summaries.audit.courses`
- `summaries.audit.files`
- `summaries.audit.totalGb`
- `summaries.audit.optimizationCandidates`
- `summaries.optimization.optimized`
- `summaries.optimization.failed`
- `summaries.optimization.savedMb`
- `summaries.registry.assetCount`
- `status`
- `steps`

如果 stdout 中有多个 JSON 块，优先使用最后一个完整 JSON。

- 管理员可以在后台创建单课发布任务。
- 管理员可以在后台创建全量发布任务。
- 后台能显示 running 状态和日志。
- 任务完成后显示审计、压缩、上传、registry 摘要。
- 失败任务可重试。
- 同一时间不会有两个 OSS/registry 写任务。
- 页面不会要求管理员手写命令。
- 已上传资源继续走 CDN。
- 未上传资源继续 fallback 本地。
- `npm run check:production-env -- --env .env.production` 通过。
- 新增 `smoke:media-jobs` 通过。

## 第一版不做

这些先不放进第一版，避免风险扩大：

- 自动删除 OSS 旧资源。
- 多进程并行上传同一个课程。
- 基于数据库的复杂任务系统。
- 非管理员可见的任务中心。
- 视频转 HLS 多码率自适应。
- Mainland CDN 自动分流。

## 当前迁移期间的注意事项

当前已有手动后台上传任务在服务器运行时，不要在任务中心开发期间让新代码自动启动第二个全量任务。

现有迁移完成前，生产后台配置应保持：

```env
MEDIA_JOBS_ENABLED=0
```

等现有 4 门课迁移完成、Moodle 播放验证通过后，再启用：

```env
MEDIA_JOBS_ENABLED=1
```

这样可以避免“命令行迁移任务”和“后台任务中心”同时写 OSS registry。
